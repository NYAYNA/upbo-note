# 냔냐 업보노트

위플랩 후원관리의 **룰렛 통계 → 시청자별** 화면을 정리하는 GitHub Pages용 정적 사이트입니다. 비공식 도구이며 위플랩과 제휴하지 않습니다.

**단컷 · 냔생복 · 방셀 · 배너 · 노래 · 움짤 · 공겜** 중 하나가 이름에 포함된 당첨만 후원자별로 정리합니다. `A 단컷`, `B 단컷`, `얼빡 방셀` 같은 원래 이름을 유지하며 완료 횟수와 남은 수량을 관리합니다.

## 사용
1. 사이트에서 위플랩 연결을 누르고 기간을 알아볼 수 있는 목록 이름을 입력합니다.
2. 연결 버튼을 북마크 바에 드래그합니다.
3. 위플랩 후원관리에서 원하는 조회 기간·프리셋을 설정하고 **더 보기**를 끝까지 불러온 뒤 룰렛 통계의 시청자별 탭을 엽니다. 통계 팝업의 이름 검색은 비웁니다. 위플랩 통계는 후원관리 화면에 불러온 목록만 기준으로 집계됩니다.
4. 저장한 북마크를 실행합니다. 새 정리 창으로 통계를 전달합니다. 팝업이 차단되면 위플랩에서 팝업을 허용해야 합니다.
5. 두 창을 유지하면 표시된 통계를 2초마다 확인해 변경된 값을 반영합니다. 위플랩 서버를 자동 조회하지 않습니다. 신규 후원 반영은 위플랩의 목록 새로고침 후 통계를 다시 열어야 합니다. 페이지 자체를 새로고침했다면 북마크를 다시 실행합니다.

조회 기간·프리셋 변경 시 새 이름으로 북마크를 만드세요. 같은 이름은 최신 스냅샷으로 교체되며 합산되지 않습니다. 날짜별 개별 이벤트·후원 금액은 해당 통계 표에 없으므로 추측하지 않습니다. 시청자별/항목별 보기, 검색, 완료 횟수, 미완료 필터, CSV, JSON 백업을 지원합니다.

이전에 저장한 당첨 횟수보다 적은 통계를 받으면 반영을 보류합니다. 같은 기간의 전체 데이터를 불러왔는지 확인하세요. 기간이 겹치는 여러 목록은 각각 독립적이며 전체 합산하지 않습니다. 기존 다른 업보책의 완료 내역을 자동 추정하거나 가져오지 않습니다.

## 저장 및 연결
- 계정 비밀번호, 쿠키, 인증 토큰을 읽거나 저장하지 않습니다.
- 북마크는 표시된 통계 DOM만 읽으며 원본 후원/알림/완료 상태를 수정하지 않습니다.
- `postMessage`는 정확한 목적지 origin으로만 전송합니다. 수신 측은 원본 origin, 창, 일회성 연결 토큰을 확인합니다.
- 후원 내역은 정리 사이트의 localStorage에만 저장됩니다. GitHub에 업로드되지 않으며 다른 기기와 동기화되지 않습니다. 브라우저 데이터 삭제 전 JSON 백업을 저장하세요.
- 통계 팝업을 닫거나 이름 검색 또는 개수별 보기로 바꾸면 전송을 보류합니다. 선택 기간을 자동 감지하지 않으므로 목록 이름으로 구분해야 합니다.
- 웹사이트의 DOM 또는 팝업 정책이 바뀌면 연결 기능을 수정해야 할 수 있습니다.
- 공개 배포 파일에 실제 사용자 후원 내역을 포함하지 않습니다. 예시 데이터는 가상입니다.

## 배포
`index.html`, `style.css`, `core.js`, `connector.js`, `app.js`를 GitHub 저장소의 루트에 올리고 Settings → Pages → Deploy from a branch → main / (root)를 선택합니다. 별도 빌드나 서버가 필요하지 않습니다.

## 검증
`node --test core.test.cjs connector.test.cjs`로 중복 통계 처리, 완료 횟수 유지, CSV 수식 방지, 입력 검증, 연결 메시지 검증과 일부 통계 전송 방지를 확인합니다. `node serve.cjs`는 개발용 로컬 미리보기입니다.
